# AGENTS.md

## General guidance

Read no-slop.md

## Purpose

This guide tells AI and human contributors how to work safely in the signalk-route-planner
repository. It is model-agnostic: map the roles below to whatever agents, modes or prompts your
tool provides.

signalk-route-planner is a Signal K server plugin and Freeboard-SK extension that plans the
shortest route through water deep enough for the boat, using signalk-underkeel's chart index,
water level and corridor route check. A wrong "safe" route can put a boat aground, so safety
behaviour outranks features and performance.

## Repository profile

- **Runtime:** Node.js Signal K plugin, TypeScript under `src/`.
- **Tests:** Jest via ts-jest under `__tests__/`, with fast-check for property tests.
- **Build output:** `lib/` is generated by `tsc`; never edit it.
- **Design source of truth:** `docs/DEVELOPMENT-PLAN.md`. Check the milestone table (§8) before
  starting work, and implement the milestone in scope rather than skipping ahead.
- **Chart data and risk model:** signalk-underkeel, through its planning API v1 (plan §2.1). This
  repository never builds a chart index of its own.

## Safety invariants

These hold in every change. A change that weakens one needs an explicit decision recorded in
`docs/DEVELOPMENT-PLAN.md` first. signalk-underkeel's seven invariants hold here as well.

1. **Every offered leg is verified.** Leg statuses come from signalk-underkeel's route check of
   the final route; the planner never sets a status itself.
2. **Unverified is never safe.** A path through water the check cannot verify is reported
   `unverified` with the reason, never ranked as `ok`.
3. **Monotonic.** A deeper draft, a taller air draft, a lower water level or a smaller accepted
   probability never yields a route that a less constrained request rejected.
4. **Hard rules stay hard.** Entry-prohibited restricted areas and traffic separation lane
   direction are never traded for distance.
5. **Never silent.** A missing planning API, an index that is not ready, a destination outside
   the chart coverage or a search that hit its work limit answers with a reason, never a route.
6. **Own data only adds caution.** The boat's own tracks may lower cost, never risk.
7. **No automatic actuation.** The plugin writes routes as unsaved drafts; it never activates a
   route or sends autopilot or steering commands.

### Safety Agent prompt

> Act as the Safety Agent. Check this diff against the safety invariants in AGENTS.md. For each
> one the diff touches, name the test that proves it still holds, or the missing test. Flag any
> path where a missing API, stale input or a work limit could return a route.

### Search Agent prompt

> Act as the Search Agent. Implement the approved change in `src/search/` or `src/plan/`
> following plan §4. Every returned route must come from the proof step. Add property tests
> against the synthetic oracle and report the work against the §6 budget.

## Coding guidelines

- Edit `src/`, never `lib/`.
- Strict TypeScript with `noUncheckedIndexedAccess`. Explicit types at public boundaries.
- Never wrap imports in `try/catch`.
- Lifecycle cleanup is deterministic: `stop()` aborts running plans and removes routes.
- All units are SI on the wire (metres, seconds, radians, m/s), as Signal K requires.
- Chart data never goes into git (`.gitignore` covers `data/`, `*.000`, `*.fgb`).
- Do not add runtime dependencies without a clear need; the plugin runs on Raspberry Pi and
  Cerbo GX class hardware.

## Validation

| Change area     | Validation                                                               |
| --------------- | ------------------------------------------------------------------------ |
| Any TypeScript  | `npm run check:ts`, `npm run check:ts:tests`, targeted `npx jest <file>` |
| Search / plan   | targeted tests plus property tests; `npm test`                           |
| Routes          | route tests with a fake router and a fake planning API                   |
| Package/release | `npm run verify:ci-local`, then `docs/release-checklist.md`              |

`npm test` must stay hermetic and under 120 s: the Signal K plugin registry runs it with no
network, a read-only home directory and `SIGNALK_REGISTRY_TEST=1` (see
`.github/workflows/plugin-test.yml`). Tests run in `__tests__/helpers/node-realm-environment.js`.
A test may make at most 5 000 `expect()` calls: collect per-element checks in a property and
assert once. CI fails `npm run verify` when the test run takes over 120 s
(`PLANNER_TEST_BUDGET_S`). Never skip a safety test or lower its fast-check runs for speed.

If a command cannot run in your environment, record the command and the failure. Do not claim it
passed.

## Pull request expectations

- Work on a branch, never on `main`; every change reaches `main` through a pull request.
- CodeRabbit reviews each pull request (`.coderabbit.yaml`); fix every real finding in a commit,
  and merge only when CI is green and every review thread is resolved.
- The description gives:
  - motivation and what changed;
  - exact validation commands run and their results;
  - which safety invariants the change touches and the tests covering them;
  - follow-up work, if any.
